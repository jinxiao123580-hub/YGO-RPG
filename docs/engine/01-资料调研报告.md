## 二、第三方生态（均已验证）

### 2.1 YGOPRODECK API v7 —— 国际数据源 ✅ 已下载
- 端点: `https://db.ygoprodeck.com/api/v7/cardinfo.php`（支持 archetype/banlist/md_rarity/misc 等过滤）
- 每卡字段: 英文名/描述、type、atk/def/level/race/attribute、**archetype（字段）**、**card_sets（卡包+稀有度+市价）**、**banlist_info（TCG/OCG 禁限）**、md_rarity（MD 稀有度）、tcg/ocg 发售日
- 限速 20 req/s；当前库版本 v147.23 (2026-10-08)
- 数据落盘: `sources/raw/cardinfo_full.json` (24.9MB, 14599 卡), `cardsets.json` (646 系列), `archetypes.json` (661 字段)

### 2.2 ocgcore / ygopro —— 规则引擎内核
- `mycard/ygopro` 仓库: `ocgcore/`(C++ 内核) + `script/`(Lua 卡片效果) + `gframe/`(客户端)
- 卡片效果全部是 Lua（`script/c{passcode}.lua`），**自定义卡=新增 cdb 条目+Lua 脚本**，生态成熟
- 脚本开发文档: ProjectIgnis `scrapi-book` (https://projectignis.github.io/scrapi-book)
- 自定义/动画卡脚本库: https://github.com/ProjectIgnis/CardScripts

### 2.3 WindBot —— 对手 AI（MDPro3 已内置）
- 上游: https://github.com/IceYGO/WindBot (MIT, C#)
- 以客户端身份连服务器打牌，AI 决策在 `Game/AI/Decks` 的 Executor；支持 `DeckFile=` 任意 .ydk
- **Dialog 机制**: `Dialogs/` 下的性格对话包（Cirno/Ecclesia/Ghoul…多语言）——NPC 人格的现成载体
- **难度分级**: MDPro3 的 bot.conf 原生支持 AI_LV1(沙包)→AI_LV4(竞技)+AI_WILD(狂野·不受禁限表)——「放水」是官方功能

### 2.4 SRVPro —— 自建服务器（剧情层接管点）
- https://github.com/mycard/srvpro (AGPL, CoffeeScript/TS)， ygopro 233 服同款
- Docker 部署，7911 端口，房间名编码控制功能（AI/比赛/云录像），内置 WindBot 在线 AI
- 玩家客户端通过 hosts.conf 指向任意服务器 → **GM 服务端可以自定义房间参数与对局流程**

### 2.5 MDPro3 —— 玩家客户端（用户选定）→ 拆解见 `02-MDPro3拆解.md`

## 三、关键结论

1. **不需要写任何规则代码**：规则层 = ocgcore（引擎）+ Lua 脚本（卡片）+ WindBot（AI 决策），全部现成。
2. **AI 的正确位置**有四个：
   - GM/叙事（跑团层，LLM 直出）
   - NPC 决策（在引擎枚举的合法动作里做选择题，人设注入）
   - 内容生产（卡池构建/NPC 卡组/剧情文本，本资料库的 card_tags 表即为其接口）
   - 教学演出（把引擎产生的合法事件翻译成剧情化的台词）
3. **「超越规则」有四个侵入度等级的落地路径**，详见 `../design/03-剧情超规则.md`。
4. **版权红线**: 卡图/卡文归 Konami/4K Media。个人非商业可用，不打包分发资源，项目内只引用 passcode。
