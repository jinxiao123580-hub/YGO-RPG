## 三、搭建过程中修复的五个问题（都已固化在代码里）

1. **SRVPro 路线否决**: srvpro 每房 spawn 一个 Linux 无头 `ygopro`（server 分支专属），Windows 无此二进制 → 改用 **YGOSharp**（WindBot 同作者官配服务器，引擎内嵌服务端）
2. **ocgcore.dll**: YGOSharp P/Invoke 原生引擎。用 MinGW g++ 16 从 Fluorohydride/ygopro-core + lua 上游直接编译出 **x64 ocgcore.dll**（`-DLUA_COMPAT_5_2`，排除 onelua.c/lua.c）
3. **sqlite3.dll**: 仓库自带是 x86 → 从 sqlite-amalgamation 3.51.3 编 x64
4. **协议坑**: YGOSharp 严格校验版本相等（`ClientVersion=4945` 必须与机器人一致）；NoCheckDeck=True（AI_BlueEyes 不过现行禁限校验）；srvpro 换 YGOSharp 后房间机制不同（单全局房，先到者为主机）
5. **三个崩溃级 bug**:
   - YGOSharp `GameAnalyser.OnConfirmCards` 缓冲区 <8 字节时数组越界 → 边界检查 + 整个分析器 try/catch（分析器无权杀死对局）
   - WindBot `LLMExecutor.Deck` 为 null（替换执行器时未继承卡组名）→ 装配时 `{ Deck = originalExecutor.Deck }`
   - WindBot Release 版吞掉对局结果日志 → 加 `[对局结束]` 永久日志行

## 四、已知遗留（不阻塞战役流程）

- WindBot `OnConfirmCards` 对空确认包 EndOfStream（Tick 级容错吞掉，对局继续）；与服务器侧同源问题，后续同款补丁
- 对局结束后机器人收尾阶段有解析异常并断连（游戏已结束，无影响；真人对局中玩家客户端是 MDPro3，不经过此路径）
- mock LLM 的回合推进显示双方在慢速换回合——真实 LLM 接入后的强度表现需另行评估（决策分级回退策略已就位）
