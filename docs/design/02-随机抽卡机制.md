# 随机抽卡机制 —— 从情节卡池中掉落

> 对应实现: `scripts/pool_draw.py` (`draw_pack` / `cmd_draw`)
> 目标: 复刻「开包的惊喜感」, 但服从剧情节奏—— UP 主把卡直接递给媳妇, 我们把这一步做成抽卡。

## 一、一包的定义

```
每包 3 张:
  - 逐张按 pool_cards.weight 加权随机
  - 保底: 若 3 张全 < R, 强制把最好的一张换成 R+ (R/SR/UR 加权)
  - 每包稀有度期望: ~1.15 R, 0.45 SR, 0.15 UR (可调 RARITY_WEIGHT)
```

权重设计要点: **weight 是剧情的乐器**。
- 剧情高光前（BOSS 战前一章）调高主角流关键卡权重 → 「命运般的抽卡」
- 沉睡卡(unlock_plot 非空) 抽中时显示「卡在发光…但它还睡着了」→ 剧情钩子
- 同卡重复不掉率递减，靠收藏系统消化（见下）

## 二、保底与重复（防挫败）

| 机制 | 规则 | 参数 |
|---|---|---|
| 包内保底 | 每包至少 1 张 R+ | 硬编码 |
| 大保底(拟加) | 连续 N 包无 SR+ → 第 N+1 包必出 SR+ | PITY_LEN=10 |
| 重复转化(拟加) | 第 4 张起转「点数」，点数可从当前章节池兑换指定卡 | 拟复刻 MD 的 CP 系统 |
| 关键卡不入池 | 剧情核心卡(主角卡/BOSS 掉落)走剧情奖励, 不靠随机 | `unlock_plot` + 剧情发放 |

## 三、可复现性与调试

- `draw_pack(seed=…)` 用确定性种子 → 存档回放、bug 复现、主播「验证掉率」都可行
- `draw_log(seq, pool_id, id, rarity, pity_used, seed)` 全量落库 → 掉率统计和曲线调参

```python
# 调参循环: 抽 10000 包看分布
python -c "from pool_draw import *; import collections; \
c=collections.Counter(); \
[draw_pack(['ch1_dragon','ch1_staple'],seed=i).forEach(lambda h: c.update(h['rarity'])) for i in range(10000)]; \
print(c)"
```

## 四、剧情节奏接口（给 GM 的 API）

GM（LLM）不直接碰数据库，只调用语义化接口:

```python
grant_card(id, reason="剧情: 圣殿守卫认可了你")   # 剧情发放, 绕过随机
set_plot_flag("ch1_boss_defeated", "true")        # 置位后沉睡卡苏醒
open_pack_screen(pool_ids, count)                  # 进入抽卡演出, 返回结果供叙事
```

**演出与机制分离**: 抽到什么由本模块决定（可复现），怎么演由 GM 决定（金光特效/龙的咆哮/UP 式吐槽）。叙事永远描述引擎/掉落模块给出的既成事实，不做虚构——这是防幻觉纪律在掉落系统的应用。
