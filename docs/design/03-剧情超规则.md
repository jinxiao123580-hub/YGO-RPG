# 剧情超规则 —— 在情节需要的时候超越规则

> 「卡片在发光」「命运的抽卡」「黑暗决斗」——动画和 B 站 UP 主都在规则外演剧情。
> 本文档定义超规则的**分级体系**与每级的技术落点，原则: **引擎可信度不被破坏的前提下, 剧情效果最大化**。

## 一、总原则：引擎是物理法则，超规则是奇迹

奇迹必须稀有才叫奇迹。超规则的正确用法是**每章节 ≤1 次、用在剧情高光**，其余时间完全守规。若每局都超规则，引擎失去裁判权威，跑团沦为过家家。

## 二、四级超规则体系

### L0 规则内演出（随时可用, 零风险）
引擎完全守规，GM 把**合法事件**演出成剧情。
- 例: NPC 抽到关键卡 → GM 演出「他的眼睛亮了」；玩家残局翻盘 → 「卡在回应你的呐喊」（其实是 WindBot LV1 放水+正常斩杀线）。
- 这是 90% 剧情时刻的实现方式。动画的「心之抽卡」本来就是这么拍的。

### L1 参数超规（房间级, 零侵入）
ygopro 房间原生支持的非标准参数，MDPro3 本地建房/SRVPro 开房都可设:
- 自定义 LP（8000→16000 打持久战 / 4000 闪电战）
- 起手手牌数、每回合抽卡数
- 关闭卡组检查（配合战役禁限表: 三幻神解禁）
- 自定义 lflist.conf（**「本章禁限表」= 剧情平衡工具**：BOSS 章禁玩家的无敌连招，叙事包装成「遗迹的封印之力」）
- tag duel（双打章节：玩家+伙伴 NPC vs 双 BOSS）

### L2 剧情卡（自定义卡, 低侵入）
**卡片本身就是剧情的容器。** 在 cards.cdb 加条目 + script.zip 加 Lua 脚本 = 效果完全可控的剧情卡:
- 动画名场面复刻: 「被封印的艾克佐迪亚」集齐即胜（本来就是官方卡）
- 新造剧情卡: 「勇者的誓言——此卡加入手卡时，回复 5000 LP」（教学章的安全网）
- BOSS 专属卡: 只存在于 BOSS 卡组里的卡，出场即演出
- 技术参照: ProjectIgnis CardScripts 生态 + scrapi-book 文档；MDPro3 自带 13226 个脚本可抄结构
- 约束: 保持「效果可被规则引擎执行」，即**超规则写在卡文里，而不是绕过引擎**——「暗游戏替你抽卡」= 设计一张「抽卡阶段代替抽卡」的剧情卡，不是改抽卡流程

### L3 流程超规（服务器级, 中侵入, 形态B可用）
GM 服务端在 SRVPro 上做流程干预:
- 强制中断: 「决斗到此为止」——第 N 回合触发剧情事件（BOSS 真面目揭露），对局以当前局面进入剧情结算
- 卡组操纵: 下一次抽卡被「命运」替换（实现: 服务端对该次 draw 事件换卡）——**这就是可编程的心之抽卡**
- 双面演出: 玩家看到对手手牌闪回等（需要客户端配合，部分退化为 GM 旁白）

### L4 剧情改判（叙事层, 保底手段）
引擎判负但剧情需要玩家「输得有意义」: GM 宣布改判（「在倒下前你看见了……」），存档走剧情分支。**注意: 改判只改变剧情走向, 不回滚对局数据**——对局记录永远保留引擎真值，改判是叠加其上的剧情层。反向同样可用（引擎判胜但剧情要求牺牲，如伙伴NPC挡刀退场）。

## 三、组合范例：第一章 BOSS 战的完整设计

```
前置(L0)   GM 旁白: 遗迹深处, 白龙的虚影浮现…
参数(L1)   房间 LP=16000, 战役禁限表(封玩家的快攻连招)
演出(L0)   BOSS 用 AI_LV2 + 青眼专属 .ydk + 骄傲性格 Dialog 包
高光(L2)   玩家集齐祭品时, GM 从剧情卡池发「苏醒的青眼」(自定义卡,
           效果=本回合从手卡特殊召唤, 演出「卡组发出了光芒」)
结算(L0/4) 正常胜负结算; 若判负 -> L4 改判为「被俘, 触发营救支线」
奖励        剧情发放: 青眼白龙 + 开启第二章卡池
```

## 四、实现优先级

| 级别 | 依赖 | 建议时点 |
|---|---|---|
| L0 | GM 提示词规范 | MVP 第一天 |
| L1 | MDPro3 本地建房/SRVPro | MVP 第一周 |
| L4 | GM 存档设计 | MVP 内 |
| L2 | 自定义卡流水线(cdb+Lua+Lite.json 同步工具) | 阶段2 |
| L3 | SRVPro fork + 事件流 | 阶段3, 视需求 |
