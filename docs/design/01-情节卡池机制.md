# 情节卡池机制 —— 由剧情决定什么卡能进卡池

> 对应实现: `scripts/pool_draw.py` + `db/ygo_campaign.db` (pools / pool_cards / plot_flags)
> 母数据: `db/ygo_master.db` (14505 中文卡 + 字段/稀有度/禁限/卡包收录)

## 一、核心思想

传统卡牌游戏的卡池按「卡包商品」划分；跑团 RPG 的卡池按**剧情阶段**划分。每一章/每个场景是一个 pool，只允许符合该情节主题、强度曲线和教学需求的卡进入——这就是 B 站 UP 主「给每一关准备卡组」的数据化。

**决定「什么卡进池」的四个依据**（全部可从 master 库查出）:

1. **主题（字段 archetype）** —— 第一章白龙遗迹 → `archetype='Blue-Eyes'`；第二章魔法书之战 → `archetype='Spellbook'`。661 个官方字段就是天然的剧情章节素材库。
2. **强度分档（tier）** —— 用禁限表(banlist) + 攻防数值 + 我们自己的 `card_tags.pool_tier` 人工/AI 打标，保证第一章没有环境炸弹。
3. **教学需求（teaching_memo）** —— 本章要教的机制需要哪些卡来演示（第一章教通召→需要高星通常怪兽+无祭品的低星卡）。
4. **剧情解锁（unlock_plot）** —— 关键卡不进随机池，作为**剧情奖励**发放；池里若有前置卡，标注沉睡条件。

## 二、数据模型

```sql
pools(pool_id, name, chapter, theme, tier, notes)
  -- theme 是给 AI-GM 看的情节描述; tier 是强度分档
pool_cards(pool_id, id, rarity, weight, unlock_plot)
  -- rarity: N/R/SR/UR 投放稀有度(可与发行稀有度不同)
  -- weight: 情节权重, 剧情偏爱的卡调高
  -- unlock_plot: 非空=沉睡卡, 抽到也不生效直到剧情 flag 置位
plot_flags(flag, value, set_at)     -- 剧情开关, GM 置位
collection(id, count, first_from)   -- 玩家收集
```

## 三、建池工作流（AI 批量生成 + 人工审校）

```
第1步  章节大纲 -> AI 提取主题词(字段名/种族/属性/关键词)
第2步  SQL 粗筛: SELECT id FROM cards_intl
        WHERE archetype=<主题> AND id NOT IN (SELECT id FROM banlist_current)
        AND <数值/星级过滤贴合 tier>
第3步  AI 逐卡打标写入 card_tags (strategy/teaching_memo/pool_tier)
        -> 用 teaching_memo 过滤出本章教学卡, 用 pool_tier 剔除超纲卡
第4步  人工审校(卡文通读, 剔除文字歧义卡), 定稿 pool_cards + weight
第5步  NPC 卡组: 从池中手选 20-40 张 -> 生成 .ydk -> 注册 bot.conf
```

## 四、示例（已实装验证）

`ch1_dragon` 池: 青眼字段非禁限卡 39 张, tier=1, 情节权重默认;
`ch1_staple` 池: 贪欲之壶/圣护/黑洞等 5 张教学泛用卡。
两池联合抽卡 10 包产出: 青眼白龙、青眼精灵龙、青色眼睛的贤士…（见 `db/ygo_campaign.db` draw_log）。

## 五、与召唤法解锁体系的咬合

章节卡池是**卡**的解锁线；召唤法（通召→祭召→仪式→融合→…）是**规则**的解锁线。两者在「章节」上对齐:

| 章节 | 解锁召唤法 | 池子主题举例 | tier |
|---|---|---|---|
| 1 | 通召+通常魔陷 | 青眼/凡骨龙族 | 1 |
| 2 | 祭召(上级) | 巨神兵/上级天使 | 1-2 |
| 3 | 仪式 | 混沌仪式(青眼混沌龙回收!) | 2 |
| 4 | 融合 | 龙骑士/元素英雄 | 2-3 |
| … | 同调/超量/连接 | 按主角流派走 | 3-5 |

仪式章正好把第一章发的青眼变成仪式素材——**早期获得的卡不贬值**，这是剧情卡池区别于商品卡池的最大设计红利。
